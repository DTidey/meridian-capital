# Ruff 0.16 Upgrade

**Spec file:** `docs/specs/15-ruff-0-16.md`
**Spec slug:** ruff-0-16
**Status:** Done
**Owner:** DTidey
**Date:** 2026-10-10

## Problem statement
- Dependabot PR #41 (ruff 0.15.17 -> 0.16.10) fails CI's Lint step, so it can't auto-merge and
  ruff updates have stalled.
- Ruff 0.16 formats Python code blocks inside Markdown by default. `ruff format --check` then
  flags 8 documentation files: 7 specs and `docs/alpaca_paper_trading.md`. No Python source
  file changes.

## Scope
In scope:
- Raising the ruff pin to 0.16.10.
- Excluding Markdown from ruff, so documentation snippets stay as written.

Out of scope / non-goals:
- Reformatting documentation code blocks.
- Enabling new lint rules.
- Any other dependency.

## Assumptions
- Code blocks in specs and guides are illustrative, sometimes pseudo-code, and deliberately
  compact. Formatting them adds no correctness value.
- Ruff's documented way to disable Markdown formatting is `extend-exclude = ["*.md"]`
  (docs.astral.sh/ruff/formatter, Markdown code formatting).

## Proposed behavior / API
### Public interface
- `pyproject.toml` `[tool.ruff]`: `extend-exclude = ["*.md"]`.
- `requirements-dev.txt`: `ruff==0.16.10`.
- CLI entry points: none.

### Inputs / outputs
- Inputs: repository files.
- Outputs: `make lint` result.
- Error handling: unchanged.

### Examples
```toml
[tool.ruff]
extend-exclude = ["*.md"]
```

## Acceptance criteria
- AC1: `requirements-dev.txt` pins ruff 0.16.10, and no other pin changes.
- AC2: With ruff 0.16.10, `make lint` (`ruff check .` and `ruff format --check .`) passes
  without modifying any file.
- AC3: Markdown files are excluded from ruff, including under the pre-commit hooks. Python
  files are still formatted and linted.

## Files changed

| File | Change |
|---|---|
| `requirements-dev.txt` | ruff 0.15.17 -> 0.16.10 |
| `pyproject.toml` | `extend-exclude = ["*.md"]` with a reason comment |

## Security considerations
- Auth/authz impact: None.
- Input handling or injection risk: None.
- Secrets or credential handling: None.
- Data exposure or privacy impact: None.
- File system access impact: None.
- Network or external service impact: None.
- Dependency or supply-chain impact: Developer tooling only (ruff). Runtime dependencies are
  unchanged.
- Security notes for reviewers/testers: Bandit and pip-audit are unaffected; ruff isn't a
  security scanner here.

## Edge cases
- Explicit file paths bypass `extend-exclude` unless `--force-exclude` is used. The pre-commit
  hooks use `pass_filenames: false`, so ruff discovers files itself and the exclusion applies.
- A new Markdown file with a Python block isn't formatted, by design.

## Test guidance
- AC1 -> `git diff main -- requirements-dev.txt`
- AC2 -> `make lint` with ruff 0.16.10 installed
- AC3 -> `ruff format --check --force-exclude <spec.md>` finds no Python files; a stdin probe
  with an `analysis/*.py` filename is still formatted; `.pre-commit-config.yaml` review

## Decision log
- 2026-10-10: Excluded Markdown rather than reformatting 8 docs (146 lines across historical
  specs 01-07). Doc snippets are illustrative; reformatting is churn with no correctness gain,
  and would make every future spec's snippets lint-sensitive.
